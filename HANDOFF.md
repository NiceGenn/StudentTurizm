# Состояние проекта и что делать дальше

поиском, карта, календарь событий, маршруты, роли и регистрация, избранное,
отзывы с модерацией, панель контент-менеджера, три языка.

1. **Сверить статусы спорных объектов** по чек-листу в `docs/08-facts.md`.

3. **Уточнить координаты.** Сейчас они привязаны к сёлам с точностью до

4. **Загрузить настоящие фотографии** через панель управления вместо
   сгенерированных заглушек.
5. **Сменить пароли** демонстрационных учётных записей, если стенд будет
   доступен из сети.

## Что известно и намеренно оставлено как есть

- Фотографий в репозитории нет: права не оформлялись, вместо них заглушки.
- Тайлы карты требуют интернета. `tools/vendor_assets.sh` решает вопрос
  только с библиотеками (Bootstrap, Leaflet), но не с тайлами.
- Английские и китайские названия сёл — транслитерации, подготовленные для
  учебной демонстрации.
- Длинные описания переведены не полностью: по ТЗ достаточно интерфейса,
  названий и кратких описаний. Незаполненные переводы откатываются на
  русский, пустых мест на страницах нет.
- Профиль пользователя ограничен ФИО и почтой, поэтому отдельная модель
  профиля не заводилась — используется штатная `django.contrib.auth.User`.

## Направления развития (задел под ВКР)

- **Конструктор маршрутов**: пользователь собирает свой маршрут из объектов,
  расстояния считаются через OSRM. Модель `RoutePoint` для этого уже готова —
  нужны пользовательские маршруты и привязка к автору.
- **REST API** на Django REST Framework и фронтенд на React. Эндпоинт
  `/api/attractions.json` — первый шаг в эту сторону.
- **Личный кабинет партнёра**: роль «оператор объекта», редактирование
  собственной карточки с модерацией изменений.
- **Аналитика**: счётчики просмотров карточек, популярные фильтры, отчёты
  для администрации округа.
- **Развёртывание**: Docker, `collectstatic` и отдача статики через nginx,
  PostgreSQL как основная СУБД, HTTPS.
- **Тестирование**: тесты интерфейса через Playwright, нагрузочное
  тестирование каталога и карты.
