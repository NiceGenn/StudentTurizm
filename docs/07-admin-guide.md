# Руководство администратора и контент-менеджера

## Установка

Самый простой способ — запустить **`START.bat`** (Windows) или `./start.sh`
(macOS, Linux) из корня проекта. Скрипт создаст виртуальное окружение,
поставит зависимости, применит миграции, загрузит демонстрационное
наполнение, запустит сервер и откроет сайт в браузере. Повторные запуски
пропускают уже выполненные шаги.

Требуется установленный Python 3.11+; на Windows при установке нужна
галочка «Add python.exe to PATH».

Вручную:

```bash
git clone https://github.com/NiceGenn/StudentTurizm.git
cd StudentTurizm
./tools/setup.sh        # окружение, зависимости, миграции, демо-контент
./tools/run.sh          # http://127.0.0.1:8000/
```

Панель управления: <http://127.0.0.1:8000/admin/>

### Демонстрационные учётные записи

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `admin12345` | администратор (полный доступ) |
| `manager` | `manager12345` | контент-менеджер |
| `ivanova`, `petrov`, `sidorova`, `guest_zh` | `demo12345` | обычные пользователи |

> Пароли учебные и лежат в открытом виде в `data/demo_users.json`. При любом
> развёртывании за пределами учебного стенда их необходимо сменить, а лучше —
> удалить демонстрационные записи и создать своего суперпользователя:
> `python sources/manage.py createsuperuser`.

### Как устроены права

Отметки «Статус персонала» (`is_staff`) достаточно, чтобы войти в панель, но
не чтобы работать с контентом: разделы будут закрыты. Права выдаёт группа
**«Контент-менеджеры»**, которую создаёт команда `seed_demo` — в неё входят
все права на модели приложения `catalog` (объекты, фото, события, маршруты,
точки, категории, сёла, отзывы, избранное) и не входят права на
пользователей.

Чтобы завести нового менеджера: **Пользователи** → **Добавить**, отметить
«Статус персонала» и включить в группу «Контент-менеджеры». Управление
пользователями остаётся только у администратора (`is_superuser`).

## Переход на PostgreSQL

По умолчанию используется SQLite, чтобы проект запускался сразу. Целевая СУБД
по ТЗ — PostgreSQL. Чтобы перейти на неё, задайте переменные окружения:

```bash
export DB_ENGINE=postgres
export DB_NAME=turizm
export DB_USER=turizm
export DB_PASSWORD=...
export DB_HOST=localhost
export DB_PORT=5432

pip install "psycopg[binary]"
python sources/manage.py migrate
python sources/manage.py seed_demo
```

## Настройки окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DJANGO_SECRET_KEY` | секретный ключ | небезопасный ключ для разработки |
| `DJANGO_DEBUG` | режим отладки | `True` |
| `DJANGO_ALLOWED_HOSTS` | допустимые хосты через запятую | `localhost,127.0.0.1,[::1],testserver` |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | доверенные источники для CSRF | пусто |
| `DB_ENGINE` | `sqlite` или `postgres` | `sqlite` |

Перед публикацией в сети обязательно: `DJANGO_DEBUG=False`, собственный
`DJANGO_SECRET_KEY`, заполненный `DJANGO_ALLOWED_HOSTS` и раздача статики
через `python sources/manage.py collectstatic`.

## Работа с контентом

Панель управления — стандартная админка Django. Разделы:

| Раздел | Что делать |
|---|---|
| **Туристические объекты** | основной контент: карточки, фотографии (вложенная форма), статусы |
| **События** | календарь: даты, село, площадка |
| **Маршруты** | маршрут и его точки с порядком (вложенная форма) |
| **Категории** | название, значок, цвет маркера на карте, порядок вывода |
| **Сёла округа** | населённые пункты и их координаты |
| **Отзывы** | модерация |
| **Избранное** | просмотр сохранённого пользователями |
| **Пользователи** | только для администратора: роли и права |

### Добавление объекта

1. **Туристические объекты** → **Добавить**.
2. Заполните название — код (`slug`) подставится автоматически.
3. Выберите категорию и село. Село оставляют пустым только для объектов вне
   округа; тогда обязательно снимите отметку «В границах округа».
4. Заполните краткое описание (оно попадает в карточку и в подсказку на
   карте) и полное описание. Абзацы разделяйте пустой строкой.
5. Раскройте «Переводы названия» и заполните английский и китайский варианты;
   то же для кратких описаний. Без перевода будет показан русский текст.
6. Укажите широту и долготу. Проще всего взять их на
   <https://www.openstreetmap.org>: правая кнопка мыши → «Показать адрес».
   Широта для округа — около 50, долгота — около 127.
7. Задайте сезонность и статус.
8. Внизу добавьте фотографии, отметьте одну как «Обложка».
9. Поставьте отметку «Опубликован» и сохраните.

### Правила заполнения статусов

Это главное, что отличает портал от простого списка ссылок.

| Статус | Когда ставить | Что обязательно |
|---|---|---|
| **Действующий** | объект работает и принимает гостей | — |
| **Строится** | объект строится, дата открытия не наступила | «Примечание о достоверности» с планируемым сроком и оговоркой, что сроки сдвигаются |
| **Планируется** | объект существует только в планах | то же |
| **Не действует** | объект закрыт, заморожен, разобран | «Примечание о достоверности» с описанием, что произошло, и предупреждением не ехать |

Дополнительные признаки:

- **«В границах округа»** — снимите, если объект расположен вне округа. Такие
  объекты выводятся отдельным блоком и не должны включаться в маршруты.
- **«Условные данные»** — поставьте, если название и услуги придуманы для
  учебной демонстрации. Тогда обязательно заполните примечание.

### Модерация отзывов

1. **Отзывы** → фильтр **«Одобрен: Нет»**.
2. Прочитайте текст (колонка «Отзыв» показывает начало, полный текст —
   внутри записи).
3. Выделите подходящие отзывы, выберите действие **«Одобрить и
   опубликовать»** и нажмите «Выполнить».
4. Отзыв появится на странице объекта и попадёт в расчёт рейтинга.

Обратное действие — **«Снять с публикации»**. Удалять отзыв стоит только
если это спам: снятый с публикации отзыв остаётся в базе для разбора.

Отклонять имеет смысл отзывы с оскорблениями, рекламой, персональными
данными третьих лиц и не относящиеся к объекту.

### Маршруты

При редактировании маршрута точки задаются во вложенной таблице: объект,
порядковый номер и комментарий. Нумеруйте с шагом 1 — по этому полю
строятся и программа, и линия на карте. Один объект не может входить в
маршрут дважды: это запрещено на уровне базы.

В маршруты нельзя включать недействующие объекты и объекты вне округа.
Для контента из справочника это проверяет `tools/check_data.py`.

## Массовая правка контента через справочник

Точечные правки удобнее делать в панели, а массовые — в `data/*.json`:

```bash
# внесите правки в data/attractions.json
python tools/check_data.py                  # проверка структуры и ссылок
python sources/manage.py seed_demo          # применить к базе
```

Загрузка идемпотентна: записи ищутся по коду и обновляются. Флаг `--flush`
полностью пересобирает контент — им удобно возвращать стенд в исходное
состояние перед демонстрацией.

## Переводы интерфейса

Тексты интерфейса живут в `sources/locale/<язык>/LC_MESSAGES/django.po`.
После правки шаблонов:

```bash
cd sources
python manage.py makemessages -l en -l zh_Hans   # собрать новые строки
# перевести пустые msgstr в .po
python manage.py compilemessages                 # собрать .mo
```

Для `makemessages` и `compilemessages` нужен пакет `gettext`
(`sudo apt install gettext`). Готовые `.mo` лежат в репозитории, поэтому
без него сайт всё равно работает на всех трёх языках.

## Резервное копирование

```bash
# выгрузка контента в файл
python sources/manage.py dumpdata catalog auth.User --indent 2 > releases/backup.json

# восстановление
python sources/manage.py loaddata releases/backup.json
```

Фотографии лежат в `sources/media/` и в git не попадают — копируйте эту
папку отдельно.

## Работа без интернета

Bootstrap и Leaflet лежат в репозитории (`sources/static/vendor/`), и
шаблоны подключают их оттуда — специально готовить ничего не нужно.
Обновить версии библиотек можно скриптом `./tools/vendor_assets.sh`.

Единственное, что требует сети, — тайлы карты с серверов OpenStreetMap.
Без интернета подложка останется серой, но маркеры, подсказки и весь
остальной портал будут работать.

## Диагностика

| Симптом | Причина и решение |
|---|---|
| `no such table` при запуске | не применены миграции: `python sources/manage.py migrate` |
| Каталог пуст | не загружен контент: `python sources/manage.py seed_demo` |
| Нет фотографий | `seed_demo` запускали с `--no-images`; запустите без флага |
| Интерфейс не переключается на английский | нет файлов `.mo`: `python sources/manage.py compilemessages` |
| Карта серая | нет доступа к серверам тайлов OpenStreetMap |
| `Не найден файл справочника` | команду запустили не из корня репозитория или удалён каталог `data/` |
| `START.bat` пишет, что нет Python | установите Python с python.org и обязательно отметьте «Add python.exe to PATH» |
| `START.bat` не смог поставить Django | нет доступа в интернет; соберите папку `wheels` на другой машине (`pip download Django Pillow -d wheels`) и положите рядом с `START.bat` |
| Нужно вернуть стенд в исходное состояние | удалите `sources\db.sqlite3`, `sources\media` и файл `.venv\.seeded`, затем запустите `START.bat` |
