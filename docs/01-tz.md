# Техническое задание

**Проект:** туристический портал Благовещенского муниципального округа
Амурской области
**Тип:** учебный проект (курсовая работа / практика), задел под ВКР
**Специальность:** 09.02.07 «Информационные системы и программирование»

## 1. Назначение и актуальность

Благовещенский муниципальный округ (27 населённых пунктов, преобразован из
Благовещенского района) окружает областной центр и включает главные
приграничные площадки региона: район Каникургана с автомобильным мостом
Благовещенск — Хэйхэ и таможенно-логистическим терминалом, международный
аэропорт Игнатьево, поймы Амура и Зеи.

Единой цифровой витрины турпотенциала у округа нет. Сведения об объектах
разбросаны по справочникам, областным порталам и социальным сетям, из-за чего:

1. **Гость не видит предложения целиком.** Чтобы понять, что есть в округе,
   нужно обойти несколько источников.
2. **Приграничный поток не удерживается в сёлах.** После открытия моста
   (10 июня 2022 года) и перевода пункта пропуска «Кани-Курган» на
   круглосуточный режим (с 3 января 2023 года) округ стал «первым касанием»
   для въезжающих из КНР, но предложение округа им не видно — тем более на
   китайском языке.
3. **Малый бизнес села теряет загрузку.** Базы отдыха, гостевые дома, пасеки
   и фермы не имеют общей точки анонса.
4. **Событиям негде анонсироваться.** Дни села, ярмарки и реконструкции
   расходятся по разрозненным пабликам.

Портал решает эти задачи: каталог с фильтрами, карта, календарь событий,
готовые маршруты и мультиязычный интерфейс в одном месте.

## 2. Границы проекта

Проект **учебный**. В нём нет и не планируется:

- интеграций с ЕСИА, Госуслугами, СМЭВ и другими государственными системами;
- реальных платежей и бронирований;
- настоящих персональных данных: все пользователи вымышленные.

Названия сёл и публичных объектов реальные — это публичная информация,
используемая для правдоподобия. Часть коммерческих карточек — условные
образцы, помеченные в интерфейсе значком «Учебные данные».

## 3. Роли пользователей

| Роль | Возможности |
|---|---|
| **Гость** | Просмотр каталога, карточек, карты, календаря, маршрутов и страниц сёл; поиск и фильтры; смена языка; регистрация |
| **Зарегистрированный пользователь** | Всё вышеперечисленное + избранное, отзыв с оценкой, редактирование профиля |
| **Контент-менеджер** (`is_staff` + группа «Контент-менеджеры») | Панель управления: CRUD объектов, событий, маршрутов, категорий, сёл, фотографий; модерация отзывов. Прав на пользователей не имеет |
| **Администратор** (`is_superuser`) | Всё вышеперечисленное + управление пользователями и правами |

## 4. Функциональные требования

### 4.1 Реализовано

| № | Требование |
|---|---|
| Ф1 | Каталог объектов с карточками, категориями и фильтрами по категории, селу и сезону |
| Ф2 | Поиск по названию, описанию и тегам |
| Ф3 | Сортировка каталога: по названию, рейтингу, дате добавления |
| Ф4 | Карточка объекта: название, категория, село, описание, галерея, координаты, карта, сезонность, статус, теги |
| Ф5 | Карта всех объектов (Leaflet + OpenStreetMap) с маркерами по категориям, всплывающими подсказками и переходом в карточку |
| Ф6 | Скрытие и показ категорий на карте |
| Ф7 | Календарь событий с фильтрами по месяцу и селу, режимом «показать прошедшие» и страницей события |
| Ф8 | Готовые маршруты: описание, длительность, сезон, упорядоченная программа, точки на карте |
| Ф9 | Страница села с агрегированными объектами и событиями |
| Ф10 | Регистрация, вход, выход, редактирование профиля |
| Ф11 | Избранное для зарегистрированного пользователя |
| Ф12 | Отзывы с оценкой 1–5 и обязательной модерацией; рейтинг объекта считается по одобренным отзывам |
| Ф13 | Панель управления на базе админки Django с действиями массового одобрения и публикации |
| Ф13.1 | Группа «Контент-менеджеры» с правами на весь контент и без прав на пользователей |
| Ф14 | Статические страницы: «О портале», «Как добраться», «Контакты» |
| Ф15 | Три языка интерфейса и контента: русский, английский, китайский |
| Ф16 | Статусы объектов (`действующий`, `строится`, `планируется`, `не действует`) и признак «рядом с округом» с визуальными метками |
| Ф17 | JSON-API `/api/attractions.json` для карты |
| Ф18 | Адаптивная вёрстка (Bootstrap 5), работа на телефоне |

### 4.2 Задел под ВКР (не входит в текущий объём)

- Конструктор маршрута пользователем с расчётом расстояний (OSRM).
- REST API на Django REST Framework и отдельный фронтенд на React.
- Личный кабинет партнёра с редактированием собственной карточки.
- Аналитика посещений, докеризация, нагрузочное тестирование.

## 5. Нефункциональные требования

| № | Требование |
|---|---|
| Н1 | Стек: Python 3.11+, Django 5.1, PostgreSQL (по умолчанию для разработки — SQLite), Bootstrap 5, Leaflet |
| Н2 | Картографическая основа — OpenStreetMap: без ключа и оплаты, обязательна атрибуция (лицензия ODbL) |
| Н3 | Проект должен запускаться сразу после клонирования одной командой (`tools/setup.sh`) |
| Н4 | Контент хранится в справочнике `data/*.json` и загружается идемпотентной командой `seed_demo` |
| Н5 | Секретный ключ, режим отладки и параметры БД читаются из переменных окружения |
| Н6 | Пароли хранятся хешами (штатный механизм Django), формы защищены CSRF-токеном |
| Н7 | Отзывы не публикуются без модерации |
| Н8 | Проект покрыт автотестами (`tools/test.sh`), справочник — валидатором (`tools/check_data.py`) |
| Н9 | Сайт должен работать без интернета: Bootstrap и Leaflet хранятся в репозитории (кроме тайлов карты) |

## 6. Структура репозитория

```
data/       справочник контента (JSON) и его описание
docs/       документация практики
releases/   выгрузки готовых версий проекта
sources/    исходный код Django-проекта
tools/      скрипты установки, запуска, проверки и подготовки к офлайну
```

## 7. Критерии приёмки

1. `tools/setup.sh` на чистой машине поднимает проект и наполняет базу.
2. `tools/test.sh` проходит без ошибок.
3. Все сценарии из [05-test-cases.md](05-test-cases.md) выполняются вручную.
4. В каталоге не менее 15 объектов, 5 событий и 3 маршрутов.
5. Интерфейс полностью переведён на английский и китайский; названия и краткие
   описания объектов переведены.
6. Ни один объект со статусом, отличным от «действующий», не подан как
   работающий, и ни один не входит в маршруты.
